# 接入与迁移

## 新项目：默认直接复制或让 AI 搭建

完整复制表和通用搭建提示词见来源工作流项目的 `README.md`。本文件复制到目标项目后仍可作为日常接入参考；默认不安装运行环境。

1. 将 `project-template/.tasks/` 复制到目标根目录 `.tasks/`。
2. 将 `skills/`、`templates/`、`docs/` 放到 `.workflow/` 下的同名目录，保留技能 references；requirements.txt 可选复制到 `.workflow/requirements.txt`。
3. 复制或合并 `project-template/docs/TASK.md`、`PROGRESS.md`；合并 AGENTS.md，按需合并 CLAUDE.md。已有文件不覆盖。
4. 在项目入口写明 `.workflow/skills/<角色>/SKILL.md`，以显式读取作为通用入口。原有技能安装位置也可继续用，但文档必须引用实际位置。
5. 补充目标项目自己的边界、模块路由、真实命令、环境数据和验收责任人。空任务区保持为空，示例不迁入。
6. 检查所有目录、入口和链接。Python 可用且依赖齐全时可加跑 validate，否则记录结构检查范围与工具未运行。
7. 需求对齐 → Architect → 用户批准 → 独立 Verification Owner → Coding Owner → 用户验收 → 归档。

本包不替 Codex、Claude Code、Zcode 注册全局配置。工具能读取项目文件时，显式读取 SKILL.md 即可使用同一流程；快捷命令与自动发现按实际工具配置处理，不推断未确认的产品能力。

## 无 Python 时怎样维护

无需 Python 的含义是：不要求安装本包的 Python 辅助工具。它不表示可以省略验证、指纹、证据或验收闸门。

| 工作 | 无 Python 时的做法 |
| --- | --- |
| 找到一张任务 | 按 Task ID 直接打开 card；只读直接 hard 前置摘要，验证角色再读 spec，实现角色再读 evidence |
| 创建与更新文档 | AI 使用文件工具按模板写入，检查 ID、引用、Owner、状态、关系与证据映射 |
| 更新 index | 从活动 card 派生生成，不能独立编造摘要或把 index 作为任务真源 |
| 计算依据指纹 | 使用目标环境已有的 Node.js、其它语言或等价能力，严格实现 data-contracts 的 canonical-json-v1 和 SHA-256；不是对 YAML 原始文本求哈希 |
| 检查文件哈希 | 使用可用的 SHA-256 工具，归档 manifest 与实际文件对应 |
| 归档 | 核对用户通过及后继 readiness，保留备份，维护归档后的路径、摘要与哈希，验证完整包后再移出活动区 |
| 执行业务验证 | 使用目标项目自己的测试和运行工具，记录真实结果，与 Python 是否存在无关 |

不要求为了避免 Python 再安装一套新工具。如果当前环境没有可用的规范化 JSON / SHA-256 能力，可以先完成搭建、需求规划和规格草稿；标明缺失验证条件，不能编造 fingerprint，也不能把缺少有效验证依据的代码任务设 ready。可由另一有相应能力的环境补齐，或用户选择启用本包工具。

AI 生成的 index / manifest 同样是派生文件，不能手工变更摘要来隐藏 card 或历史差异。没有运行 taskctl 时报告“人工/AI 结构复核，taskctl 未运行”，不能写工具 PASS。人工复核不具备完整自动检查的保证。

工作流不因此增加第二套卡片格式：无 Python 与工具模式使用相同的任务、规格、证据和哈希契约，今后可以启用 taskctl 继续校验。

## 已有仓库

先备份目标工作树中的入口、任务库、技能与文档；保留未提交变更。逐文件检查冲突，不使用覆盖安装。已有模块规范继续保留，将根入口改为条件路由，不批量加载。

- 有同名技能：比较角色边界及 references，选择或合并一个权威版本，避免同名规则来源不明。
- 有其它任务系统：决定保留外部系统作为调度入口，还是使用本地任务卡。一个事实只能有一个可编辑真源；外部看板若存在，只保存 Task ID 与链接，避免双写状态。
- 有旧任务清单或旧流程：本包不提供旧清单转换器，也不带入来源项目的切换例外。先备份并确定哪些是当前有效任务，按新契约显式映射；已结束历史保留在原系统，需要时引用，不作为新项目活动任务。
- 已经在执行而缺少编码前规格：不要补写并声称独立。记录缺口，由负责人决定在原流程收尾，或重新界定尚未实现的范围进入新流程。不得伪造 ready。

## 多仓库与并行

选一个协调仓库保存 `.tasks`，证据记录每个实际修改仓库的 HEAD 与工作树快照；任务范围明确仓库及接口。归档中的哈希只校验工件文件，不能替代代码快照。

`parallelism` 是可并行性描述，不是自动派发指令。共享工作区领取须由单一协调者串行持久化 Owner；本工具没有锁或原子 claim。不同工作树可以隔离实现，但需协调任务真源和合并，不能各自声称唯一 Owner。hard 边阻塞领取；integration_order 仅阻塞指定集成验证；coordination 要求协调共享资源。

## 后续工作包

旧架构有后继任务或归档引用时不要覆盖。可在 architecture.md 按工作包保留边界章节，新任务引用所属章节；必要时将历史架构保存为版本化文档并同步明确引用。全局验收后的阶段摘要留在 PROGRESS.md。
